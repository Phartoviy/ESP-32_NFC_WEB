# NFC Web ESP32 — Arduino IDE

Прошивка для **обычного ESP32 DevKit / ESP32-WROOM-32** и PN532 по I²C.
Управление с телефона или компьютера через локальную веб-страницу на русском.
Экран, кнопки, SD-карта, Bluetooth, LittleFS и сторонние Arduino-библиотеки не нужны.

## Возможности

- Сканирование ISO14443A: UID, ATQA, SAK; распознавание Classic 1K/4K по SAK.
- Подтверждение NTAG213/215/216 командой GET_VERSION; совместимые клоны могут выдавать тот же ответ.
- Чтение всей пользовательской памяти NTAG213/215/216 в HEX.
- Отображение первой короткой NDEF-записи UTF-8 Text или URI с распространённым префиксом; остальные форматы доступны в HEX.
- Запись одной NDEF-записи: текст UTF-8 (включая русский) или HTTP/HTTPS-ссылка.
- Чтение/запись одного блока Classic 1K/4K с известным ключом A или B.
- Проверка результата записи чтением; сохранение результата в TXT через браузер.
- Проверка UID перед операцией; подтверждение записи в интерфейсе.
- Случайный пароль Wi-Fi при первом запуске, сохраняется в NVS. Токен HTTP-сеанса защищает от запросов с посторонних веб-страниц.

## 1. Подключение

Отключите питание перед монтажом.

| PN532 | ESP32 DevKit/WROOM-32 |
|---|---|
| VCC | 3V3, если плата PN532 поддерживает питание 3,3 В |
| GND | GND |
| SDA | GPIO21 |
| SCL | GPIO22 |

PN532 должен быть в режиме **I²C**. У ELECHOUSE V3: SW1=ON, SW2=OFF.
У другой платы сверяйте переключатели с её маркировкой/инструкцией.
Переключайте режим при выключенном питании; затем полностью переподключите питание.
IRQ и RESET для этой прошивки не нужны: драйвер опрашивает байт готовности по I²C.
**RSTO — выход, не подключайте его как вход сброса.**

Используйте короткие провода 10–15 см. Линии SDA/SCL должны иметь подтяжки к 3,3 В;
на многих модулях они уже есть. Если подтяжек нет, поставьте по резистору 4,7 кОм от SDA и SCL к 3V3.
Не подавайте 5 В на GPIO ESP32. Схема питания зависит от конкретной платы PN532.
Антенну не размещайте вплотную к металлу. На время операций оставляйте одну метку на антенне.

Для ESP32-C3/S3 требуется выбрать соответствующую плату и свободные GPIO в коде.
Приведённая распиновка и готовая проверка сборки относятся к обычному ESP32.

## 2. Подготовка Arduino IDE

1. Установите Arduino IDE 2.x.
2. В `Файл → Настройки → Дополнительные ссылки для Менеджера плат` добавьте:
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
3. В Менеджере плат найдите **esp32 by Espressif Systems**.
4. Для воспроизводимой сборки выберите **2.0.17**. Именно с ней проверяется этот архив.
5. Распакуйте архив. Откройте **NFC_Web_ESP32/NFC_Web_ESP32.ino**.
   Файлы `Pn532I2c.h`, `NdefCodec.h`, `WebPage.h` должны оставаться в той же папке.
6. Выберите `Инструменты → Плата → esp32 → ESP32 Dev Module`.
7. Для обычной платы с 4 МБ памяти: Flash Size — 4MB; Partition Scheme — Default 4MB with spiffs;
   PSRAM — Disabled (если на плате её нет). Название spiffs в схеме не означает, что скетч использует файловую систему.
8. Выберите свой USB-порт. Нажмите **Проверить**, затем **Загрузить**.

Библиотеки WiFi, WebServer, Wire, Preferences входят в пакет ESP32.
Устанавливать Adafruit PN532, AsyncTCP, NimBLE или ArduinoJson **не требуется**.
Предыдущие файлы ESP32 NFC Tool не копируйте в этот скетч.
Стандартная таблица разделов используется автоматически; править CSV не нужно.

Если на `Connecting...` нет продолжения — удерживайте BOOT до начала записи, затем отпустите.
Закройте другие программы, открывшие этот порт. После загрузки нажмите EN/RESET.

## 3. Первый запуск и веб-интерфейс

1. Откройте монитор порта Arduino IDE на **115200 бод**.
2. Нажмите EN/RESET. В журнале будет:
   - `PN532 OK` либо описание ошибки модуля;
   - `WiFi: NFC-ESP32`;
   - `Password: NFC-...` — индивидуальный пароль вашего устройства;
   - `Browser: http://192.168.4.1` (ориентируйтесь на фактический адрес в журнале).
3. Подключитесь с телефона/ПК к Wi-Fi **NFC-ESP32**, введя пароль из журнала.
4. Если телефон предлагает отключиться из-за отсутствия интернета, выберите сохранение подключения.
5. Откройте **http://192.168.4.1** в браузере, именно HTTP.

Логина admin нет: доступ получают устройства, знающие пароль этой Wi-Fi-сети.
Пароль Wi-Fi сохраняется при обычной перезагрузке. Полная очистка flash/NVS создаст новый пароль.
Подключение к домашнему роутеру, OTA и облачный сервис не реализованы.
Веб-интерфейс запускается даже при отсутствующем PN532; после исправления подключения нажмите
«Перезапустить NFC». При зависании модуля полностью снимите питание с обеих плат.

## 4. Чтение и запись NTAG

1. Поднесите метку; нажмите **Сканировать**.
2. Для чтения нажмите **Прочитать память и NDEF**.
3. Для записи выберите текст или ссылку, введите содержимое и нажмите **Записать NDEF**.
4. Подтвердите запись; не перемещайте метку до окончания.
5. После успеха можно проверить результат чтением и телефоном с NFC.

Поле ограничено **240 байтами UTF-8**, даже у NTAG216. Один русский символ обычно занимает два байта.
С учётом NDEF максимальный текст для стандартной NTAG213 — **134 байта**, URI — **136 байт**.
Прошивка проверяет фактическую вместимость по типу и CC. Слишком длинная запись отвергается до записи.

Запись заменяет NDEF начиная со страницы 4. UID, CC, lock-биты и пароль не изменяются.
При обнаружении любых статических/динамических lock-битов запись консервативно запрещается,
даже если часть памяти ещё доступна. Защищённые AUTH0 страницы также не записываются.
Нестандартный CC, неподтверждённый тип, NTAG203 и другие семейства для записи NDEF не поддерживаются.

Сначала устанавливается пустой TLV, затем данные записываются и проверяются по страницам,
затем фиксируется первая страница NDEF. При отключении питания/удалении метки возможна частичная
запись: автоматического отката нет. Верните метку и повторите запись. Остаток предыдущего содержимого
после нового NDEF не стирается — это не функция безопасного уничтожения данных.

## 5. MIFARE Classic

Раскройте секцию Classic. Укажите:
- десятичный номер блока (1K: 0–63, 4K: 0–255);
- тип ключа A/B;
- известный ключ сектора: 6 байт, например `FFFFFFFFFFFF` для некоторых новых меток;
- для записи — 16 байт HEX, например `00112233445566778899AABBCCDDEEFF`.

По умолчанию выбран блок 4. Чтение и запись зависят от ключа и access bits сектора.
Ключ `FFFFFFFFFFFF` подходит не всем картам. Подбор ключей не реализован.
Запись блока 0 и sector trailer запрещена. В 4K учтены большие сектора: после блока 127
служебными являются 143, 159, 175, 191, 207, 223, 239 и 255.

Чтение trailer не раскрывает Key A; возвращаются данные, разрешённые картой.
Запись произвольных блоков Classic не создаёт автоматически NDEF/MAD для телефона.
При успешной записи и отказе последующего чтения интерфейс сообщает, что проверка не выполнена.

## Ограничения и диагностика

- Частота PN532 — 13,56 МГц. Брелоки 125 кГц не поддерживаются.
- Только reader/writer ISO14443A. Нет эмуляции, UID-клонирования, поддержки DESFire-приложений,
  банковских операций, ISO15693 или универсального копирования защищённых карт.
- Для неизвестной ISO14443A-метки доступно обнаружение UID; не обещается чтение всей её памяти.
- GET_VERSION/SAK не доказывают подлинность чипа. UID используется для контроля выбора, не как криптографическая аутентификация.
- Один запрос выполняется за раз; во время чтения/записи веб-ответ может задерживаться.
- `PN532 не отвечает по I2C 0x24`: проверьте питание, режим I²C, SDA/SCL и общий GND.
- `status 0x..`: метка убрана, операция не поддерживается, защита или неправильный ключ.
- На Linux `Permission denied`: проверьте группу доступа к порту (на Ubuntu обычно `dialout`);
  `sudo usermod -aG dialout "$USER"`, затем выйдите из сеанса и войдите снова.
- `Device busy`: закройте screen, Arduino Serial Monitor и другие программы, использующие порт.

## Исходники и проверка

`Pn532I2c.h` — ограниченный драйвер PN532: стандартные короткие кадры, ACK, checksum,
таймауты, polling без IRQ. Он не предназначен как универсальная реализация всех команд PN532.
`NdefCodec.h` — кодирование NDEF, проверка HEX и защищённых блоков.
`WebPage.h` — автономная веб-страница; внешних CDN нет.

В `tests` — тесты кодека и драйвера с моделью I²C. Запуск на Linux с g++:

```bash
g++ -std=c++14 -Wall -Wextra -Werror tests/test_codec.cpp -o /tmp/test_codec
/tmp/test_codec
g++ -std=c++14 -Wall -Wextra -Werror -Itests/stubs tests/test_driver.cpp -o /tmp/test_driver
/tmp/test_driver
```

Состояние фактической сборки и проверок смотрите в `VALIDATION.md`.
Проверки в среде разработки не заменяют испытания на реальном PN532. Начните с отдельной тестовой метки.
